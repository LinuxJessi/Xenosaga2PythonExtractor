# z-ai/glm-5.3

## Findings

### (a) Code defects

1. **Dead alignment check in `vif.walk` (MPG).** `if p & 4 == 0:` parses as `p & (4 == 0)` = `p & False` = 0 — the MPG 8-byte-alignment guard never fires. Harmless on this data (no MPG claimed), but the walker is advertised as strict; a misaligned MPG would be walked silently. Refute: `python3 -c "print(4 & 4 == 0)"` prints True; a unit test with a misaligned MPG would expose it.
2. **`keep` is computed and never used in `to_glb`.** Post-weld degenerate triangles are exported anyway and counted in `n_tris`. Silent: the GLB can contain zero-area triangles and the reported triangle count inflates. Evidence: search for `keep` — assigned, never read.
3. **`d.node is None` is conflated with node 0 in `to_glb`.** `by_node.setdefault(d.node if d.node is not None else 0, ...)`, then `nd = p.nodes[node_i]` and `nd.matrix.T` are applied. A draw with no items (node None) drawn in a file whose node 0 has a non-identity matrix gets node 0's transform — silent misplacement. `check()` distinguishes `None`; `to_glb` does not.
4. **The cull byte is parsed and ignored.** `Item.cull` (item+0x1C: 0 = two-sided, 1/2–3 = culled with opposite signs, sent to VU address 0x3C6) is read into the object and never consulted. The exporter instead orients every triangle by its vertex normals and marks everything double-sided. The one field that carries per-draw facing information is unused — see (b).
5. **The ALPHA register is decoded and ignored.** `MaterialState.alpha` is stored, but `_alpha_mode` decides OPQUE/BLEND/MASK from a group-name string heuristic ("alpha" in group names). Alpha semantics are sitting in the file and not used.
6. **Latent V4-5 decode is wrong.** `unpack_words`/`unpack_data` treat V4-5 as 16 bits per vector with the 4th element at `v >> 15`. The hardware packs 4×5-bit elements across 32-bit units (bits 19:15 of the pair); the size calculation and element extraction are both incorrect. Untouched by this game's data, but the walker will silently mis-decode any V4-5 stream it is pointed at.
7. **No negative-determinant check.** If a node or bind matrix mirrors (negative determinant), `trs_from_matrix` emits negative scale, which many glTF consumers ignore — mirrored parts come out with flipped winding. Given the winding anomalies in (b), a determinant census of `node_mats` and `inv_bind` should be a gate. Evidence: compute `np.linalg.det` over all 944 files' matrices; currently nobody has.
8. **Colour clipping hides evidence.** `np.clip(c / 128.0, 0, 1)` silently clamps any byte >128, so if the real scale is not 128 = 1.0 (question d), the data that would show it is destroyed in the output. At minimum count and report clipped values.
9. **CLAMP wrap modes 2 and 3 are both collapsed** (`2→CLAMP_TO_EDGE`, `3→REPEAT`). Mode 3 with region-repeat windows is exactly the mechanism that legitimises out-of-range UVs; mapping it to plain REPEAT can visibly change tiling for the two |uv| ≈ 11175 batches.
10. **Self-tests are circular for the decode.** `_synthetic` builds files to the same layout assumptions the decoder implements; only `vif.walk`'s arithmetic is tested against an independent construction. The strip rule, batch layout and skinning gates are never tested against data not authored by the same assumption set. The three-model Blender spot-check is also weak for winding: double-sided materials mean Blender cannot reveal a facing error.

Sound, in one line each: `Batch.triangles()` parity/suppression algebra matches the stated rule and the docstring; `ibm = m.T` (row-vector → column-major glTF) and `local.T` into `trs_from_matrix` are internally consistent; `unpack_data` sign/zero extension for V4-32/8 and V2-32 is correct; `bind_error` is a genuinely non-circular check (see e); the strict-failure walk over 3.58 M commands with zero unknowns is a real tiling proof.

### (b) Winding

11. The likely mechanisms, in order of testability: (i) the **cull byte at item+0x1C** — the sign (1 vs 2/3) directly encodes which face is front for that draw, and 0 marks genuinely two-sided draws; (ii) **mirrored instances**: negative-determinant node matrices flip effective winding — check whether the 3.5 % / whole-draw reversals correlate with `det(node_mats[node]) < 0`; (iii) a **sign in the VU1 backface/clip test** — but program 2 was *not studied* and 1/3/4 only pattern-checked, so nothing about the VU-side cull is actually established; (iv) two-sided materials (cull == 0), consistent with the agent's own annotation. The exporter should decide winding from the cull byte sign plus the node-matrix determinant, not from vertex normals (normals are shading data; smooth-shaded triangles on silhouettes can legitimately disagree, and per-triangle flipping by normals breaks strip-coherent orientation). Confirm: for each draw with cull ≠ 0, test whether the cull sign predicts the normal-agreement direction; if it does in ~100 % of draws, that's the rule.

### (c) Restart rule vs header triangle count

12. Strong but not conclusive. The header count is a *total over the file*; any rule with the same total per strip reproduces it. Two distinct failure modes survive the 944/944 test: (i) if the header count was computed by the engine as Σn − 2·(#batches) − (#restarts) — which is *this exact rule* — the test is tautological; (ii) alternative rules differing only in rare adjacency cases (flag at k and k+1, flag within 2 of strip start) match the total unless those cases occur. Refuting/converging test: find batches where two flags are ≤2 vertices apart or a flag sits at strip position 0/1 — those are the discriminating cases; if the corpus contains enough of them and the count still matches, the rule is pinned. Also state the per-file restart histogram so the reader can see the count is not degenerate (e.g., zero restarts).

### (d) What can be settled where

- **Colour scale, alpha modes: files + microcode alone.** The ALPHA register value is already in hand (finding 5); the byte→float constant is a VU1 multiply constant in program 0 (readable now). No GS dump needed. Currently neither is used.
- **UV range: files alone, mostly.** WMS/WMT are decoded; the two extreme batches should be checked for mode 2/3 and the region window (WOR/WOX are in the CLAMP qword). If they are region-repeat, |uv| up to 11175 may be legitimate; if not, that's a real unexplained anomaly.
- **The 15 skeletons: files alone.** Try alternative Euler orders and JO-before-R vs R-before-JO per mismatching record and see which restores `invBind·world = I`; also the "bytes not read" in each record plausibly hold a per-joint rotation-order flag. Cross-validate on the 544 matching files.
- **Handedness, final cull/winding, rendered colour/alpha: need a GS dump (or in-emulator comparison).** No file-internal invariant can distinguish a globally mirrored export; the bind test is convention-agnostic.

### (e) Rest-pose agreement

13. Circular as stated. `skeleton_from` *sets* `world[j] = inv(invBind[j])`, so the skinning product is `pos · invBind · inv(invBind) = pos` by construction — the 1.14e-6 test only verifies the exporter's own matrix algebra and the GLB round-trip, not that the engine uses these matrices, these joint indices, or these weights. The non-circular evidence that exists is `bind_error`: `invBind[j] · world(xhr)[j+2] = I` across 544/559 files — that's genuinely independent (two files, one convention each). A stronger non-circular test: skin a mesh with a *game animation pose* (a runtime .xhr/animation matrix set) and compare against an emulator frame capture; or against a GS dump of the game drawing the same model, which simultaneously settles winding (b) and handedness.
